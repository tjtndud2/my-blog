## 1. Java의 기본 구조와 실행 과정

### 1-1. 기본 구조

```java
package com.wanted.a_basic;

public class Main {
    public static void main(String[] args) {
        System.out.println("Hello World!!!~");
    }
}
```

- Java 프로그램은 모두 **클래스 안에서** 동작합니다. 클래스 밖에는 코드를 작성할 수 없습니다.
- `main()` 메서드가 **프로그램의 시작점(entry point)** 입니다. JVM은 실행할 때 이 메서드를 찾아 호출합니다.

**`public static void main(String[] args)` 뜯어보기**

| 키워드 | 의미 |
|---|---|
| `public` | 어디서든 접근할 수 있습니다. JVM이 외부에서 호출해야 하므로 필요합니다. |
| `static` | 객체를 만들지 않고도 호출할 수 있습니다. 프로그램 시작 시점에는 아직 객체가 없기 때문입니다. |
| `void` | 반환값이 없습니다. |
| `main` | JVM이 약속된 이름으로 찾는 메서드 이름입니다. |
| `String[] args` | 실행할 때 넘겨주는 명령행 인자(문자열 배열)입니다. |

- `package` 선언은 파일이 속한 폴더 구조(`src/com/wanted/a_basic`)와 일치해야 합니다.
- 파일 이름은 `public class` 이름과 같아야 합니다. (`Main` → `Main.java`)

### 1-2. 실행 과정

```
[Main.java] --javac(컴파일)--> [Main.class (바이트코드)] --JVM--> [OS별 기계어] --> 실행
```

1. Java 코드를 작성합니다. (`.java`)
2. JDK에 들어 있는 **javac(컴파일러)** 가 `.java` 파일을 `.class` 파일(**바이트코드**)로 번역합니다.
3. **JVM**이 `.class` 파일을 불러옵니다.
4. JVM이 바이트코드를 읽어 각 OS에서 실행할 수 있는 기계어로 바꿉니다.
5. 바뀐 기계어가 실행됩니다.

> 💡 **추가 설명**
> - **JDK**(Java Development Kit): 개발 도구 모음입니다. 컴파일러(javac)와 JRE가 들어 있습니다.
> - **JRE**(Java Runtime Environment): 실행 환경입니다. JVM과 표준 라이브러리가 들어 있습니다.
> - **JVM**(Java Virtual Machine): 바이트코드를 실제로 실행하는 가상 머신입니다.
> - 바이트코드는 OS와 상관없는 중간 코드이고, OS별 차이는 JVM이 맡습니다. 그래서 Java는 **"Write Once, Run Anywhere"** (한 번 작성하면 어디서든 실행)라고 불립니다.
> - IntelliJ에서 실행하면 컴파일된 결과가 `out/production/...` 폴더에 `.class` 파일로 생깁니다.

## 2. 리터럴과 변수

### 2-1. 리터럴이란?

**리터럴(literal)은 코드에 직접 적은 "값" 그 자체**입니다. 정수, 실수, 문자, 문자열, 논리값이 있습니다.

```java
int i = 10;          // 10      → 정수 리터럴
double d = 3.14;     // 3.14    → 실수 리터럴
char ch = 'ㅎ';      // 'ㅎ'    → 문자 리터럴 (작은따옴표)
String str = "안녕";  // "안녕"  → 문자열 리터럴 (큰따옴표)
boolean bl = true;   // true    → 논리 리터럴
```

- **변수**는 값을 담는 이름 붙은 저장 공간이고, **리터럴**은 그 공간에 넣는 값입니다.

### 2-2. 기본 자료형 (Primitive Type)

| 분류 | 자료형 | 크기 | 표현 범위 / 비고 |
|---|---|---|---|
| 정수 | `byte` | 1byte (8bit) | -128 ~ 127 |
| 정수 | `short` | 2byte | -32,768 ~ 32,767 |
| 정수 | `int` | 4byte | 약 -21억 ~ 21억 (**정수 기본형**) |
| 정수 | `long` | 8byte | 매우 큰 정수, 리터럴 뒤에 `L`을 붙입니다 |
| 실수 | `float` | 4byte | 리터럴 뒤에 `f`를 **반드시** 붙입니다 |
| 실수 | `double` | 8byte | **실수 기본형**, 더 정밀합니다 |
| 문자 | `char` | 2byte | 유니코드 문자 한 글자 (`'A'`, `'ㅎ'`) |
| 논리 | `boolean` | 1byte | `true` / `false` |

```java
float f = 3.14f;   // f가 없으면 컴파일 에러
double d = 3.14;
```

> 💡 **추가 설명**
> - 실수 리터럴 `3.14`는 기본적으로 **double(8byte)** 로 취급됩니다. `float`(4byte)에 넣으려면 `f`를 붙여 "이건 float 값"이라고 알려야 합니다. 그렇지 않으면 크기가 큰 double을 작은 float에 넣는 셈이라 컴파일 에러가 납니다.
> - 정수 리터럴은 기본적으로 **int**입니다. int 범위를 넘는 값을 쓸 때는 `long l = 10000000000L;`처럼 `L`을 붙여야 합니다. 소문자 `l`은 숫자 `1`과 헷갈리므로 대문자를 씁니다.
> - `String`은 기본 자료형이 아니라 **참조 자료형(클래스)** 입니다. 그래서 대문자 `S`로 시작합니다.

### 2-3. 변수의 선언과 초기화

```java
int num;        // 선언: int 크기의 공간을 만들고 이름을 num으로 정함
num = 30;       // 초기화: 처음으로 값을 넣음

int num2 = 10;  // 선언과 초기화를 한 번에
```

- **같은 영역(`{}` 블록) 안에서는 같은 변수 이름을 두 번 선언할 수 없습니다.** 그래서 실습에서도 `str`, `str2`처럼 이름을 다르게 지었습니다.
- 지역 변수는 **초기화하지 않고 사용하면 컴파일 에러**가 납니다.

## 3. Scanner로 키보드 입력 받기

```java
import java.util.Scanner;

public class Application02 {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("당신의 이름을 입력하세요 : ");
        String name = sc.nextLine();

        System.out.println("이름 : " + name + " 입니다!");
    }
}
```

**실행 예시**
```
당신의 이름을 입력하세요 : 홍길동
이름 : 홍길동 입니다!
```

- `import java.util.Scanner;`: 다른 패키지에 있는 `Scanner` 클래스를 가져와 씁니다.
- `new Scanner(System.in)`: 표준 입력(키보드)에서 값을 읽는 Scanner 객체를 만듭니다.
- `sc.nextLine()`: 엔터를 누를 때까지 입력한 **한 줄 전체**를 문자열로 읽습니다.
- `print`는 줄을 바꾸지 않고, `println`은 출력한 뒤 줄을 바꿉니다.

> 💡 **추가 설명: 자주 쓰는 Scanner 메서드**
> | 메서드 | 읽는 값 |
> |---|---|
> | `nextLine()` | 한 줄 전체 (공백 포함) |
> | `next()` | 공백 전까지의 단어 하나 |
> | `nextInt()` | 정수 |
> | `nextDouble()` | 실수 |
>
> ⚠️ `nextInt()`를 쓴 뒤 바로 `nextLine()`을 쓰면, 버퍼에 남은 **엔터(개행 문자)** 를 읽어 빈 문자열이 들어갑니다. 이럴 때는 중간에 `sc.nextLine();`을 한 번 더 호출해 개행을 비워 줍니다.

> 💡 **IntelliJ 단축어**
> - `sout` → `System.out.println();`
> - `soutv` → `System.out.println("변수명 = " + 변수명);` (디버깅 출력에 편리합니다)
> - `psvm` 또는 `main` → `public static void main(String[] args) {}`

## 4. 형변환 (Type Conversion)

형변환은 **어떤 자료형의 값을 다른 자료형으로 바꾸는 것**입니다. 두 가지 방식이 있습니다.

### 4-1. 암시적(묵시적) 형변환: 작은 타입 → 큰 타입

```java
int num2 = 100;         // 4byte
double dnum2 = num2;    // 8byte → 자동 변환, dnum2 = 100.0
```

- 작은 그릇의 값을 큰 그릇에 옮기는 것이라 **데이터가 손실되지 않습니다.** 그래서 컴파일러가 알아서 바꿔 줍니다.
- 변환 방향: `byte → short → int → long → float → double` (`char → int`도 가능)

### 4-2. 명시적 형변환: 큰 타입 → 작은 타입

```java
double dnum = 99.99;     // 8byte
int inum = (int) dnum;   // 4byte, (자료형)을 직접 적음

System.out.println("dnum = " + dnum);  // dnum = 99.99
System.out.println("inum = " + inum);  // inum = 99
```

- 큰 그릇의 값을 작은 그릇에 담으면 **데이터가 손실될 수 있습니다.** 위 예시에서는 소수점 아래가 **반올림이 아니라 버림**되어 `99`가 됩니다.
- `int inum = dnum;`처럼 `(int)` 없이 쓰면 컴파일러가 손실 가능성 때문에 **에러**를 냅니다.
- 손실을 감수하고 변환하려면 `(자료형)`을 **명시적으로 적어** 개발자가 의도했다는 것을 표시해야 합니다.

> 💡 **정리**: 에러가 나는 것은 "형변환을 적지 않은 채 큰 타입을 작은 타입에 넣는 경우"입니다. `(int)`처럼 명시적 형변환을 적으면 컴파일은 되지만, 값은 잘릴 수 있습니다.

## 5. 연산자

실습에서 사용한 값은 `int a = 10;`, `int b = 3;`입니다.

### 5-1. 산술 연산자 (`+`, `-`, `*`, `/`, `%`)

```java
System.out.println("덧셈 : " + a + b);     // 덧셈 : 103
System.out.println("덧셈 : " + (a + b));   // 덧셈 : 13
System.out.println("나눗셈 : " + (a / b)); // 나눗셈 : 3
System.out.println("나머지 : " + (a % b)); // 나머지 : 1
```

**⚠️ 문자열과 `+` 연산**
- 문자열이 `+`를 만나면 다른 피연산자를 **문자열로 바꿔서 이어 붙입니다.**
- `+`는 **왼쪽에서 오른쪽으로** 계산합니다.
  - `"덧셈 : " + a + b` → `"덧셈 : 10" + b` → `"덧셈 : 103"`
  - `"덧셈 : " + (a + b)` → 괄호를 먼저 계산 → `"덧셈 : " + 13` → `"덧셈 : 13"`
- 숫자끼리 먼저 더하고 싶다면 **괄호로 묶어야 합니다.**

> 💡 **추가 설명**
> - **정수 / 정수 = 정수**입니다. `10 / 3`은 `3.333...`이 아니라 `3`이고, 소수점은 버려집니다. 실수 결과가 필요하면 `(double) a / b`처럼 한쪽을 실수로 바꿉니다. → `3.3333333333333335`
> - `%`(나머지, mod 연산)는 **짝수·홀수 판별**(`n % 2 == 0`)이나 **배수 판별**에 자주 씁니다.

### 5-2. 비교 연산자 (`==`, `!=`, `<`, `>`, `<=`, `>=`)

두 값을 비교해 `true` / `false`를 돌려줍니다.

```java
boolean isGreater = a > b;                      // true
System.out.println("a > b : " + (a > b));       // a > b : true
System.out.println("a != b : " + (a != b));     // a != b : true
```

- 프로그래밍에서 `!`는 **NOT(부정)** 을 뜻합니다. `!=`는 "같지 않다"입니다.
- `=`는 대입이고, `==`는 비교입니다. 헷갈리지 않도록 주의합니다.

### 5-3. 논리 연산자 (`&&`, `||`, `!`)

여러 **조건을 결합**해 최종 참/거짓을 판단합니다.

| 연산자 | 의미 | 결과 |
|---|---|---|
| `A && B` | AND | 둘 다 참일 때만 `true` |
| `A \|\| B` | OR | 하나라도 참이면 `true` |
| `!A` | NOT | 참과 거짓을 뒤집음 |

```java
boolean isTrue = true;
boolean isFalse = false;
System.out.println("둘 다 참이니? : " + (isFalse && isTrue));        // false
System.out.println("둘 중 하나는 참이니? : " + (isFalse || isTrue)); // true
```

> 💡 **면접 질문 고찰: `A && B`에서 A를 앞에 둘 때와 B를 앞에 둘 때의 차이는?**
>
> 핵심은 **단축 평가(Short-Circuit Evaluation)** 입니다.
> - `A && B`: **A가 `false`이면 B는 아예 계산하지 않습니다.** 결과가 이미 `false`로 정해졌기 때문입니다.
> - `A || B`: **A가 `true`이면 B는 계산하지 않습니다.** 결과가 이미 `true`로 정해졌기 때문입니다.
>
> 그래서 조건의 **순서**가 성능과 안전성에 영향을 줍니다.
> 1. **성능**: `&&`에서는 **거짓일 확률이 높거나 계산 비용이 적은 조건**을 앞에 두면 불필요한 연산을 줄일 수 있습니다. (`||`에서는 참일 확률이 높은 조건을 앞에 둡니다.)
> 2. **안전성**: 앞의 조건이 뒤의 조건을 보호할 수 있습니다.
>    ```java
>    if (str != null && str.length() > 0) { ... }  // 안전
>    if (str.length() > 0 && str != null) { ... }  // str이 null이면 NullPointerException
>    ```
> 3. **부수 효과**: 뒤쪽 조건에 `++` 같은 값 변경 코드가 있으면, 앞 조건의 결과에 따라 실행될 수도, 안 될 수도 있습니다.
>
> 참고로 `&`, `|`(하나짜리)는 단축 평가를 하지 않고 양쪽을 모두 계산합니다.

### 5-4. 증감 연산자 (`++`, `--`)

변수의 값을 1씩 늘리거나 줄입니다. 연산자의 **위치**에 따라 결과가 달라집니다.

| 형태 | 이름 | 동작 |
|---|---|---|
| `++age` | 전위 연산 | **먼저 1을 더하고**, 그 값을 사용 |
| `age++` | 후위 연산 | **현재 값을 먼저 사용하고**, 그다음 1을 더함 |

```java
int age = 20;
System.out.println("초기 값 age : " + (age));  // 20
System.out.println("++age : " + (++age));     // 21 (증가 → 사용)
System.out.println("age : " + (age));         // 21
System.out.println("age++ : " + (age++));     // 21 (사용 → 증가)
System.out.println("age : " + (age));         // 22
```

## 6. 🤔 생각해볼 문제: `byte` 127 + 1은 왜 128이 아닐까?

```java
byte bnum = 127;
bnum++;
System.out.println(bnum);   // 128이 아니라 -128 출력!
```

### 키워드별 설명

**① bit와 byte**
- **bit**는 0 또는 1을 저장하는 가장 작은 단위이고, **1byte = 8bit**입니다.
- `byte`는 8bit이므로 2⁸ = **256가지** 값을 표현할 수 있습니다.
- 가장 왼쪽 bit는 **부호 비트**(0이면 양수, 1이면 음수)이므로 범위는 **-128 ~ 127**입니다.

**② 2진수로 보는 127 + 1**
```
  0111 1111   (127, byte의 최댓값)
+ 0000 0001   (1)
-----------
  1000 0000   → 부호 비트가 1이 됨 → -128
```
- Java는 음수를 **2의 보수** 방식으로 저장합니다. 이 방식에서 `1000 0000`은 **-128**입니다.

**③ 오버플로우 (Overflow) / 언더플로우 (Underflow)**
- **오버플로우**: 자료형이 표현할 수 있는 **최댓값을 넘으면** 최솟값 쪽으로 돌아갑니다. → `127 + 1 = -128`
- **언더플로우**: **최솟값보다 작아지면** 최댓값 쪽으로 돌아갑니다. → `-128 - 1 = 127`
- 자동차 주행거리계가 `999999` 다음에 `000000`으로 돌아가는 것과 비슷합니다. Java는 이때 **에러를 내지 않고** 조용히 값이 바뀌므로 특히 주의해야 합니다.

**④ 형변환 (Type Casting)과의 관계**
- `byte`끼리 연산해도 Java는 먼저 값을 **int로 바꿔서 계산**합니다. (int 미만 타입은 연산할 때 int로 승격됩니다.)
- 그래서 `bnum = bnum + 1;`은 int 결과를 byte에 넣으려는 것이므로 **컴파일 에러**가 납니다.
- 반면 `bnum++`와 `bnum += 1`은 내부적으로 `bnum = (byte)(bnum + 1);`처럼 **명시적 형변환이 자동으로 들어갑니다.**
- 즉 int로 계산한 `128`(`0000 0000 ... 1000 0000`)을 byte로 형변환하면서 **아래 8bit만 남고**, 그 값 `1000 0000`이 `-128`로 해석됩니다.

> ✅ **한 줄 정리**: `byte`는 8bit라서 -128~127만 표현할 수 있습니다. 127에 1을 더하면 오버플로우가 일어나고, int 결과를 byte로 형변환하며 아래 8bit(`1000 0000`)만 남아 2의 보수 규칙에 따라 -128이 됩니다.
>
> 실무 팁: 오버플로우가 걱정되면 더 큰 타입(`int`, `long`)을 쓰거나, `Math.addExact()`처럼 오버플로우 때 예외를 던지는 메서드를 사용할 수 있습니다.

## 7. 핵심 요약 체크리스트

- [ ] Java 코드는 클래스 안에서 동작하고, `main()`이 프로그램의 시작점이다.
- [ ] `.java` → (javac) → `.class` 바이트코드 → (JVM) → 기계어 순서로 실행된다.
- [ ] 리터럴은 값 자체이고, 변수는 값을 담는 이름 붙은 공간이다.
- [ ] 정수 기본형은 `int`, 실수 기본형은 `double`이다. `float`에는 `f`, `long`에는 `L`을 붙인다.
- [ ] 같은 블록 안에서는 같은 변수 이름을 두 번 선언할 수 없다.
- [ ] `Scanner`와 `nextLine()`으로 키보드 입력을 받는다. `nextInt()` 뒤 개행 문제에 주의한다.
- [ ] 작은 타입 → 큰 타입은 자동(암시적) 형변환, 큰 타입 → 작은 타입은 `(타입)`을 적는 명시적 형변환이 필요하다.
- [ ] 문자열 + 숫자는 문자열 연결이 된다. 숫자 계산을 먼저 하려면 괄호를 쓴다.
- [ ] 정수끼리 나누면 소수점이 버려진다.
- [ ] `&&`, `||`는 단축 평가를 하므로 조건 순서가 중요하다.
- [ ] 전위(`++a`)는 증가한 뒤 사용하고, 후위(`a++`)는 사용한 뒤 증가한다.
- [ ] 자료형 범위를 넘으면 오버플로우/언더플로우가 일어난다. (`byte` 127 + 1 = -128)
